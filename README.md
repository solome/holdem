# Holdem · 掬一捧的德州好牌图鉴

在线访问：[solome.github.io/holdem](https://solome.github.io/holdem/)。

该入口沿用账号现有的 GitHub Pages 自定义域名，会跳转至 [solome.js.org/holdem](https://solome.js.org/holdem/)。两者指向同一份页面。

一个可离线打开的德州扑克 HTML 页面，顶部导航切换 **起手牌矩阵**、**成就图鉴**、**牌力计算** 与 **牌局复盘**。

四页均支持简体中文、繁體中文和 English。扑克牌采用四种花色配色：黑桃黑色、梅花绿色、红桃红色、方片蓝色；未达成成就仍统一置灰。

## 起手牌矩阵

提供紧凶（TAG）、标准（Balanced）、松凶（LAG）三套学习预设，可选择自己的位置（UTG、HJ、CO、BTN、SB、BB）和前面行动：**无人入池、一人平跟、一人加注**。面对平跟或加注时，还可选择对手位置，选项仅包含在你之前行动的合法位置，均假设没有其他跟注者。默认展示 **BTN 面对 CO 加注**，可随时切换。

13 × 13 矩阵展示全部 169 类起手牌，对角线为对子，上半区为同花、下半区为非同花。不同颜色区分加注、跟注、免费过牌与弃牌；加注按场景对应首次加注、隔离加注或 3-bet，小盲跟注平跟者时展示为补齐盲注。点击手牌可查看全部具体花色组合：对子 6 种、同花 4 种、非同花 12 种；同时提供行动构成、三风格对比及范围文字复制。

**主动入场占比 =（加注 ∪ 跟注）的组合数 ÷ 1,326**，按具体组合统计，不按矩阵格子数量计算。大盲面对平跟可免费过牌的组合单独标记，不计入该比例；此数值描述当前预设，不是实战 VPIP 统计。

适用条件为 **6 人现金桌、100 BB 有效筹码、无前注或跨式盲注**。平跟者投入 1 BB；加注者加注至 2.5 BB，小盲加注至 3 BB。UTG 最先行动，仅适用无人入池；BB 在其余玩家全弃时直接赢取底池，切换为面对平跟或加注后可查看应对范围。小盲无人入池时简化为加注或弃牌，面对加注时简化为 3-bet 或弃牌。未覆盖面对再加注、多人底池或锦标赛 ICM，需按抽水与对手调整。

面对平跟与加注的入场数据独立定义，不复用无人入池的 RFI 开池范围。三套范围均为本项目原创学习预设，**并非 GTO、求解器结果或参考网站的逐格图表**。起手牌与前序行动原则参考：

- [PokerStars：翻牌前基础](https://www.pokerstars.com/poker/learn/lesson/pre-flop-essentials/)
- [Upswing Poker：大盲防守](https://upswingpoker.com/podcast/ep3-big-blind-defense/)
- [Upswing Poker：应对平跟者](https://upswingpoker.com/limps-poker-open-limpers-strategy/)

## 牌力计算

输入自己的 **2 张起手牌**，再选择 **翻牌 3 张、转牌 4 张或河牌 5 张公共牌**，计算到河牌时的最终牌型概率。可加入一位对手并输入其 2 张起手牌，计算双方单挑的成牌分布与胜率。52 张牌按四种花色配色展示，已被其他位置使用的牌不可重复选择。

计算排除全部已知手牌与公共牌，**等概率枚举所有合法的后续公共牌组合，不使用随机抽样**。对手未加入时只计算自己的成牌概率；加入对手后，其手牌也从剩余牌堆中排除。

| 当前公共牌阶段 | 仅输入自己手牌 | 输入双方手牌 |
| -------------- | -------------- | ------------ |
| 翻牌（3 张）   | 1,081 种组合   | 990 种组合   |
| 转牌（4 张）   | 46 种组合      | 44 种组合    |
| 河牌（5 张）   | 1 种结果       | 1 种结果     |

每种结果从自己的 2 张手牌与 5 张公共牌中选出 **最佳 5 张**，可使用 0、1 或 2 张手牌。结果仅归入最终最佳牌型：高牌、一对、两对、三条、顺子、同花、葫芦、四条、同花顺或皇家同花顺。皇家同花顺独立统计，10 类互斥，原始概率合计 100%；页面显示的概率经四舍五入。支持按概率或牌型大小降序排列。

单挑结果分别显示 **我获胜、平局、对手获胜** 的概率；**我的底池权益 =（获胜次数 + 平局次数 ÷ 2）÷ 总结果数**，与获胜概率分开显示。

页面初始不预填牌面，点击「载入示例」才使用示例。修改牌面或切换公共牌阶段后会清除旧结果，补齐牌面并再次点击「计算概率」即可更新。

点击牌位可编辑同一组手牌或公共牌：顶部只用于切换牌位，牌库中的牌点击一次选中，再次点击同一张取消；空位选牌后自动移到下一个空位。牌面不再叠加删除叉号，底部只保留「取消／完成」。点击「完成」才保存本次修改；「取消」、关闭按钮、Esc 或点击遮罩均放弃本次修改，并保留原牌面与计算结果。

聚焦牌位后也可按 Delete / Backspace 移除。使用「撤销」可恢复上一次牌面修改（包括删除、清空、阶段或对手变更），并恢复该牌面原有的计算结果；连续修改只保留最近一步撤销。

## 牌局复盘

入口为 `#review`，按翻牌前、翻牌、转牌、河牌回看已收录牌局：展示当前已发公共牌、各位牌友的手牌、行动顺序、概率，以及当时的想法。腾腾、克林、星星、掬一捧、敏敏、旺旺和尖尖使用固定姓名与头像；星星和掬一捧在两手牌中复用同一身份。内部牌谱 ID 仅供计算，不展示为角色名。

页面底部「一起玩牌的人」是一张七人趣味牌桌。首次随机入座后，人物的物理座位保持固定；每次“再来一局”只把庄位顺时针推进一位，小盲、大盲及其他位置标签随之轮转。桌布采用两端饱满的跑道形轮廓，桌面宽高约 2.1:1，深绿桌沿与细内线增加层次；小头像在桌面采用上三、下二、两端各一，手机采用上三下四。头像和位置常显，当前阶段已弃牌的头像置灰并加“已弃牌”标识，切回弃牌前的阶段会恢复。悬停或聚焦头像，浮窗展示姓名、起手牌、当前成牌、累计投入、后手、模拟风格和行动原因，手机可点按查看；弃牌头像仍可查看。大家共用一副无重复的牌，每人两张手牌与五张公共牌。

默认从「翻牌前」（Preflop，常简称「翻前」）开始，此时公共牌尚未发出，浮窗仅显示 AKs、AA 等起手牌组合，不提前判断成牌或赢家。切换翻牌、转牌、河牌时，公共牌、底池和浮窗内容同步变化。河牌只比较未弃牌者的最佳五张，平局共同分池。四个阶段对应 [德州扑克的四轮下注](https://www.pokerstars.com/poker/games/texas-holdem/)。这桌明确标为趣味模拟，敏敏、旺旺和尖尖仍未出现在真实牌谱中。

发牌随机，行动由独立下注引擎与每位玩家的决策器共同生成。小盲投入 0.5 BB，大盲投入 1 BB，未入池的其他位置弃牌不扣筹码。引擎维护合法下注、最小加注增量与待回应队列；每位玩家独立选择过牌、下注、跟注、加注或弃牌，翻牌、转牌、河牌均可价值加注、再加注及过牌后加注。价值进攻、真实听牌的半诈唬与纯诈唬分别处理。每位玩家有自己的进攻、跟注、诈唬倾向与种子随机序列，同一局刷新后行为可复现。

这些风格参数仅用于模拟，不代表真人玩法。决策器只接收自己的两张牌、当前已翻出的公共牌和公开的筹码／行动，不读取对手底牌、未来牌或对手的内部意图。浮窗中的“持续下注基准”和“诈唬基准”是机会合适时的模拟倾向，不是获胜概率。参数与分层说明见 [模拟引擎文档](docs/poker-simulator-engine.md)。

当前策略第 5 版使用前端 JavaScript **德州决策引擎**。七位玩家通过同一接口，根据自己的手牌、位置、筹码和公开行动推测对手范围；每次决策默认抽样 128 组无撞牌的对手手牌及后续公共牌，比较弃牌、过牌、跟注与合法下注／加注尺度的增量预期收益（BB）。模拟风格只调整收益接近时的选择和进攻频率，不强制跟负收益的贵注。具体架构、API、计算公式与边界见 [德州决策引擎文档](docs/holdem-decision-engine.md)。

强起手牌的隔离金额随平跟人数和位置调整；翻后识别最后一位翻前加注者，结合牌面、人数、真实听牌和公开施压决定持续下注、延迟持续下注、转牌继续下注或控池。AK、JJ 用于回归检查，任意合法手牌都走同一范围／权益／收益流程。模型估计单轮对手回应，尚不搜索后续街的完整博弈树，因此收益是近似值，不是 GTO 结果，也不保证长期盈利。

此前宽松策略第 3／4 版的两批 10,000 局曾测得翻前结束／看到翻牌／三人以上看翻牌为 **9.61%／90.39%／61.50%** 与 9.56%／90.44%／61.24%。这些是历史校准结果；第 5 版优先比较行动收益，不再把 10%／90%／60% 作为硬性配额，不能沿用旧频率。历史方法与数据保留在 [策略校准报告](docs/friend-table-calibration.md)，起手牌矩阵的学习范围保持独立。

浮窗显示当前行动与简短原因，已经弃牌的玩家保留最后一次行动。底池由实际投入累加，弃牌后不再投入，未被跟注的筹码退回；其他人全弃时立即收池，停止后续发牌，并禁用结束阶段之后的按钮。后手指留在玩家面前的筹码，底池单独展示，未计入赢家后手。引擎不限制加注次数，但当前模拟用可覆盖筹码上限保留无全下／边池的范围，不含前注和抽水；属于可解释的简化规则，并非 GTO 或真实胜率求解器。原则参考 [翻牌前基础](https://www.pokerstars.com/poker/learn/lesson/pre-flop-essentials/)、[底池赔率](https://www.pokerstars.com/poker/learn/lesson/pot-odds/)与[德州扑克行动规则](https://www.pokerstars.com/poker/games/texas-holdem/)。

首次发牌写入 `localStorage`（键仍为 `holdem.friend-table.v1`，记录格式升级为 version 3）。`seatOrder` 和 `seatIndex` 保存固定物理座次，`buttonSeat` 与 `handNumber` 保存庄位和手数。升级会保留合法旧七人局的座位、起手牌、预发公共牌和起始筹码，补齐固定座次并重新生成行动。「再来一局」保持人物座次，庄位顺时针移动一格，重新发牌及安排这手的模拟起始筹码，并回到翻牌前；七局轮完所有位置。刷新、切换页面／语言／案例不会发新牌或移动庄位。界面不显示缓存机制说明。不同浏览器和站点地址各自保存；存储不可用时仅在本次访问保留。无效或不兼容的原始牌局会自动重建。

腾腾、克林、星星、敏敏、旺旺、尖尖的卡通头像根据用户提供的照片生成，优先明显卡通化，保留少量辨识线索，风格参考掬一捧的 GitHub 头像，并为各人安排不同的浅色背景；掬一捧直接采用 [solome 的 GitHub 原头像](https://github.com/solome)，保存为本地快照，不重新绘制。头像使用手型指针；鼠标悬停或键盘聚焦时显示放大的头像与姓名，触屏设备可点按查看。玩法特点暂留空，后续按真实补充更新。

头像资源存放在 `src/assets/avatars/`，通过 `src/review-avatar-urls.js` 静态导入并在构建时内嵌为 data URL；离线打开页面无需请求 GitHub 或其他图片服务。朋友的原始照片不复制到项目，生成与来源说明见 [头像资源说明](src/assets/avatars/README.md)。

每手牌先记下朋友局的背景与心情，再回看牌面。第一手收录“最后一把，快乐一把”、深筹码和已投入 8 BB 的当时考虑，以及提前看到加注强度时可能弃牌的回想；第二手记录星星的小盲位置和熟人间的诈唬印象，同时说明这手实际是 QQ。河牌后的栏目改为“留下的回忆”，数学仍保留，记忆不做输赢评分。内容编辑在 `src/review-cases.mjs`，固定身份、头像路径与待补充特点维护在 `src/review-people.mjs`，不虚构未记录的下注、位置或朋友原话。

- **四人底池**：JJ、87 同花、AA、A5 同花；已知最终主池 80 BB，边池 24 BB 与 6 BB，各自按有资格参与的玩家计算。掬一捧以 55566 葫芦收池。
- **单挑听牌**：QQ 对 97 同花；按星星本手开始 260 BB、掬一捧约 120 BB、翻牌加注到 60 BB 解读。掬一捧最后需跟约 52 BB，争夺约 240 BB；星星未匹配的约 140 BB 退回。掬一捧的 789TJ 顺子最终胜出。

概率是**所有已记录起手牌已知、只使用当前街公共牌**的事后精确枚举，未知弃牌不作额外假定，尚未发出的实际转牌／河牌不提前排除。独赢率、平局率与分池加权权益分别展示；边池仍扣除无资格玩家的已知手牌。它们不等于行动时针对未知对手范围的策略建议，也不以最终输赢判断决策好坏。

| 牌局 | 翻前组合 | 翻牌组合 | 转牌组合 | 河牌结果 |
| --- | ---: | ---: | ---: | ---: |
| 四人 | 1,086,008 | 820 | 40 | 1 |
| 单挑 | 1,712,304 | 990 | 44 | 1 |

概率由 `npm run generate:reviews` 生成并保存至 `src/review-equity-data.mjs`，页面直接读取，离线也可切换。测试将快速评牌器与原有最佳五张算法交叉验证，并重新枚举所有八个阶段，防止数据与算法失配。修改收录手牌时，同时更新 `REVIEW_EQUITY_DEALS` 并重新生成概率。

底池仅统计已知投入，未含可能弃牌的盲注、前注及抽水；第二手筹码为约数。分析区明确区分半诈唬加注与后续跟全下的决策节点。规则参考：[底池赔率](https://www.pokerstars.com/poker/learn/lesson/pot-odds/)、[补牌与概率](https://www.pokerstars.com/poker/learn/lesson/calculating-outs/)、[边池规则](https://www.pokerstars.com/help/articles/poker-rules-master/217459/)。

## 直接使用

用现代浏览器打开根目录的 `index.html` 即可。页面的样式、脚本、扑克牌和牌友头像全部内嵌，**无需安装依赖、启动服务或联网**，复制这一个 HTML 文件即可分享。

默认简体中文。语言选择保存在当前浏览器的本地存储中；浏览器禁用本地存储时仍可切换语言，但关闭后不会保留。

成就图鉴当前只支持查看预置记录，未实现成就页面录入、用户账号或后端存储。

新增或修改记录时，编辑 `src/catalog.mjs` 中的 `RECORDS`，以成就 ID 为键存放记录数组，每次命中追加一个对象，填写 `hole`（2 张）和 `board`（5 张）。可选 `date` 为成就达成日期，使用真实日期的 `YYYY-MM-DD` 字符串；可选 `opponent` 为该次牌局对手的 2 张手牌。两个可选字段均兼容省略或 `null`，不影响旧记录。以下是当前 7 金刚的记录数组，后续真实命中可继续追加：

```js
"quads-7": [
  {
    date: "2026-09-24",
    hole: [card("7", "spades"), card("5", "spades")],
    board: [
      card("A", "hearts"), card("7", "clubs"), card("7", "hearts"),
      card("7", "diamonds"), card("3", "diamonds"),
    ],
    opponent: [card("K", "clubs"), card("A", "diamonds")],
  },
  // 在此追加下一次命中的日期和牌局；同一天的记录也单独追加。
],
```

花色使用 `spades`、`hearts`、`clubs`、`diamonds`，牌点使用 `2`–`10`、`J`、`Q`、`K`、`A`。每次牌局内的全部手牌与公共牌不可重复，对手最终牌型仅根据该次手牌和公共牌选出最佳五张。记录按日期从新到旧展示，无日期的记录排在最后；同日记录保留原始顺序，不合并或覆盖。日期、牌面无效或不符合目标牌型的记录会被过滤，不影响同一成就的其他合法记录。新增记录后，需同步调整测试中的记录断言；只有首次达成新成就才增加已达成数量。

```sh
npm ci         # 首次安装构建依赖，也可使用 npm install
npm run build  # 重新生成可独立打开的 index.html
npm run check  # 检查脚本语法、运行数据测试并重新构建
npm run analyze:friends -- --hands 192 --samples 24 --seed 20260929 # 低预算整桌检查
npm run analyze:friends -- --hands 192 --samples 128 --diagnostics --benchmark # 生产预算统计与诊断
npm run dev    # 构建并在 http://127.0.0.1:4173 本地预览，需要 Python 3
```

修改 `src/` 中的源码后重新构建；直接修改 `index.html` 会在下次构建时被覆盖。

界面的字体、间距、圆角与图标规范见 [DESIGN.md](DESIGN.md)。尺寸变量统一定义在 `src/styles.css`，关闭按钮复用 `src/icons.mjs` 的 SVG，保持不同页面和设备上的对齐一致。

## GitHub Pages 发布

发布流程定义在 [`.github/workflows/pages.yml`](.github/workflows/pages.yml)。每次推送 `main` 都会自动安装锁定依赖、运行全部测试、构建页面，再发布到 **https://solome.github.io/holdem/**。只有检查成功后才会部署。

在仓库 [Settings → Pages](https://github.com/solome/holdem/settings/pages) 中，将 **Build and deployment → Source** 设置为 **GitHub Actions**。使用此工作流时无需选择 `main / root` 或创建 `gh-pages` 分支；发布分支由工作流中的 `push.branches: [main]` 控制。

项目没有单独设置 CNAME，当前继承账号站点的 `solome.js.org` 域名。HTTPS 访问由该域名现有的 Cloudflare 配置提供；如需调整账号域名或源站证书，应在对应域名／账号站点配置中处理，而不是修改本项目的构建路径。

可以在 [Actions → Deploy GitHub Pages](https://github.com/solome/holdem/actions/workflows/pages.yml) 查看构建和部署结果，也可以选择 `main` 后点击 **Run workflow** 手动重新发布。

本地检查发布产物：

```sh
npm ci
npm run check
node scripts/package-pages.mjs
```

`_site/` 只包含生成的 `index.html` 和 `.nojekyll`，不上传源码、测试或开发依赖。也可运行 `npm run build:pages` 直接构建并打包。页面使用内嵌资源和 hash 导航，支持 `/holdem/`、`/holdem/#ranges` 和 `/holdem/#odds`，不需要额外的路径重写配置。
